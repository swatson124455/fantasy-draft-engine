# Spec 00 — Data Acquisition

The gate. Everything in Phase 1+ assumes we have the data. This spec lists every data source we need, what we expect to find, where to look, and the audit output we need before scoping later methods.

---

## Why this matters

The v2 plan claimed "~2.5M historical BBM rosters" but full pick-by-pick rosters with outcome labels for BBM I–VI are not all publicly available in one place. Some methods (vine-copula tail dependence with stable estimation, causal forest on rare position-composition contrasts, Leiden consensus over 50 runs) need tens of thousands of observations per cell. If we end up with 200K rosters that's plenty. If 20K, conservative thresholds and sampling strategies are required.

**Phase 0 exit criterion:** a one-page audit answering, for each data category, "do we have it, partially have it, or have to build/buy it." Method thresholds in Phases 2–4 are calibrated against the audit.

## Acquisition methods (priority order)

1. **Free public data** — nflverse, Sleeper, public Underdog/DK ADP pages, Wayback. Use first; everything we can get free we get free.
2. **Manual CSV upload** — for one-off finalist data (BBM tweets/threads). Loader UI in Phase 0.4.
3. **Semi-automated scrape** — politely rate-limited, respects robots.txt, runs nightly.
4. **Paid data** — only if a category is critical and free is genuinely empty. Document the cost; don't surprise the user.

## What we do if data is thin

1. **Reduce scope of vine-copula matrix** to most-played 200 players instead of full pool.
2. **Reduce K=6 archetypes to K=4** if archetype model can't be reliably trained.
3. **Drop bootstrap-BCa to bootstrap-percentile** if compute is the constraint.
4. **Skip causal-forest position-composition contrasts** below an N threshold per cell.
5. **Lean harder on the CLV gate** (Phase 9.6) — patterns require live confirmation before we trust them.

This is fine. The plan is robust to data scarcity; it just means a smaller initial signal set with the diagnostic engine catching up over seasons via the data flywheel.
